# Recommendation Engine v2 — Reference Analysis and Migration Plan

## Reference repository findings

| Repository | Source-level finding | Reusable idea / limitation |
|---|---|---|
| [Anime_Recommender](https://github.com/MAdhavbhatia222/Anime_Recommender) | `Files_Repo/Training.py` fills missing `GENRE`, vectorizes genres with `TfidfVectorizer(stop_words='english')`, and saves `linear_kernel` similarities plus a title-index pickle; `Predict.py` loads those artifacts and returns nearest rows. | Keep corpus building separate from serving and use sparse TF-IDF/cosine. Avoid its dense all-pairs matrix, title-only key, and hardcoded fallback. Its prediction test checks an HTTP request but does not validate ranking quality. |
| [Anime_Recommendations_System](https://github.com/kunal-mallick/Anime_Recommendations_System) | `model/model.ipynb` includes user-user cosine over a user×anime ratings pivot and a user/item embedding regressor whose model/training cells are commented out; the notebook loads a pickle. It remaps IDs, converts `-1` to `0`, min-max scales scores, uses a random 90/10 split, and appears to concatenate the first ratings CSV twice. | Keep seen-item filtering and consider neighbor/embedding outputs as separate candidate signals, but do not treat missing ratings as zeros or assume a working hybrid. No automated tests or temporal/per-user ranking evaluation were found. |
| [AI_Movie_Anime_Recommendation](https://github.com/ChiragRaiCR7/AI_Movie_Anime_Recommendation) | `src/data_loader.py` builds title/synopsis/genre text; `src/vector_store.py` chunks LangChain documents and persists Chroma using default `all-MiniLM-L6-v2`; the pipeline retrieves with default top-k and sends context to Groq `RetrievalQA`. | Reuse index/retrieval separation and evidence-based retrieval, not the hosted LLM or mandatory model download. No tracked tests; persistence/version behavior and runtime paths are weakly verified. |
| [cine-sage-recommends_2](https://github.com/madalamanikanta/cine-sage-recommends_2) | `src/pages/Recommendations.tsx` reads Supabase genre/studio fields, maps supported genres to Jikan IDs, fetches sorted results concurrently, deduplicates MAL IDs, and caps lists at 24. Two Jikan clients each have a fixed delay, but direct recommendation-page fetches bypass it/status checks. | Reuse bounded, deduplicated candidate discovery; don't mistake saved preferences for history-based ranking. Tests cover preference UI, not Jikan discovery/favorites/history integration. |
| [anime-recommendation](https://github.com/paras603/anime-recommendation) | `Anime-recommendation.py` uses sparse TF-IDF (1–3 grams, `min_df=3`, English stop words) and `NearestNeighbors(metric='cosine')`, fitting the neighbor model on each request. It asks for 10 neighbors then removes the query item, so returns at most 9. | Sparse cosine retrieval is suitable; cache/reuse the model, test zero vectors/small catalogs, and use normalized exact matching. No repository tests were found. |
| [anigator](https://github.com/Salierigator/anigator) | Two-stage serving retrieves a top-200 warm shortlist from 128-D user/item representations, then LightGBM LambdaRank reranks with 29 user/item/cross features. `serve.py` masks seen items and handles cold items separately; tests/docs include padding and exported-encoder parity contracts. | Reuse candidate-pool filtering, train/eval/serve feature contracts, and cold-item distinctions. The ranker and retriever require trained artifacts/data, and source docs don't define a universal duplicate-ID policy; v2 uses a deterministic scorer and explicit dedupe instead. |
| [AnimeRecBERT](https://github.com/MRamazan/AnimeRecBERT) | `models/bert.py` uses masked item prediction over item-token sequences (no explicit user-ID embedding; configured mask probability .15). GUI inference right-pads, scores the final position, then filters top-k results, which can underfill and has no explicit seen-item logit masking. | Keep a future adapter boundary only. Full-vocabulary attention/output projection and large interaction datasets are costly; no checked-in tests were found and the checkpoint/transformer stack is unsuitable as a first-run requirement. |

## Existing application baseline

- The desktop application uses PySide6 and SQLite; `Anime` and `Literature` are dataclasses backed by existing persistence. Recommendation entry points include `RecommendationDialog`, the main window, and dashboard/panel integrations.
- The current service path comprises `user_preference_analyzer`, `anime_similarity`, `recommendation_discovery`, `jikan_recommendation_service`, `recommendation_scorer`, `recommendation_cache`, and `recommendation_engine`. It currently mixes profile computation, provider discovery, local history candidates, scoring, and UI result projection.
- Python package import succeeds using `.venv/Scripts/python.exe`; `scikit-learn` is not installed. `pyproject.toml` currently declares only PySide6 as a runtime dependency.
- Baseline focused recommendation/Jikan tests: **69 passed**. Baseline complete suite: **416 passed, 1 failed**. The failure is `tests/test_backend_lifecycle.py::test_backend_starts_and_responds`, which expects 506 anime and observes 507. Do not change library data to mask it.
- Existing working-tree edits before v2 implementation are preserved; no commit/push or production-database writes are permitted.

## Migration decisions

1. Introduce `animevault.recommendation` as a small, testable core with normalized profile, candidate/result models, sparse content retrieval, provider interfaces, transparent ranking/diversity, separate feedback, cache, and evaluation utilities. Do not create placeholder modules.
2. Keep current `Anime`/`Literature` and SQLite schema semantics unchanged. Read through existing models; store recommendation feedback in a separate file-backed store for now, avoiding a migration and any library-row writes.
3. Use scikit-learn's sparse TF-IDF and cosine operations for catalogue retrieval; declare it explicitly and keep a documented graceful offline path if the optional package is absent. No dense all-pairs matrix, transformers, GPU, or paid API.
4. Jikan expands candidates only. Retrieve genre IDs from the actual genre catalogue, bound requests, cache responses persistently, and isolate provider errors. The local profile and scorer determine personalized ordering.
5. Introduce the new engine behind the existing independent Recommendation window; preserve its visual design and user-initiated Add to Library action. Retire old recommendation modules only after imports and tests demonstrate they are no longer used; unrelated provider/poster code remains intact.
6. Validate offline and with a copy of the active database. Do not call destructive initialization/migrations on the user's database. Keep the outstanding 506/507 backend test mismatch explicitly documented.

## Test strategy

Test profile signal conflicts and deduplication, sparse retrieval with missing synopsis, deterministic ranking and negative evidence, candidate filtering/deduplication, provider failure/cache fallback, isolated feedback writes, ranking metrics, and UI integration. Automated tests must not use live network. Report live Jikan behavior separately from mocked tests; a timeout is not an empty catalogue.
