# Windows packaging

The canonical application version is in `src/animevault/_version.py`. The Windows build script reads it and stages each build under `dist/release-v<version>-<timestamp>/`, keeping previous outputs intact.

## Build the Windows installer

Build on Windows; PyInstaller does not cross-compile. Use a Python environment with the project dependencies and PyInstaller installed, plus **Inno Setup 6** (`ISCC.exe`) for the installer step:

```powershell
python -m pip install -e .
python -m pip install pyinstaller
winget install JRSoftware.InnoSetup
.\packaging\build_windows.ps1
```

The script freezes the application with PyInstaller, then invokes `packaging/AnimeVault.iss` through Inno Setup. The installer is named **`AnimeVault-Setup.exe`** and is written to the same versioned `dist/release-v.../` directory as the frozen `AnimeVault/` application folder. The temporary PyInstaller work files go in the corresponding `build/release-v.../` directory.

If Inno Setup is missing, the script reports that it skipped the installer and exits successfully after producing the frozen app. Use `-SkipInstaller` to intentionally build only that portable app directory.

### Alternative self-extracting installer

`build_installer.py` is a separate alternative that creates `dist/AnimeVault-Setup.exe` without Inno Setup. It requires an existing `dist/AnimeVault/` PyInstaller output and a Python environment with PyInstaller and the application build dependencies; it also uses PowerShell to create shortcuts. This script does **not** run automatically from `build_windows.ps1` and does not use that script's versioned staging directory.

```powershell
python -m pip install -e .
python -m pip install pyinstaller
# First build or place the frozen application in dist/AnimeVault/.
python .\packaging\build_installer.py
```

Both build paths produce an installer named `AnimeVault-Setup.exe`; use the versioned output from the Inno Setup build as the standard release artifact.

## Publish as a GitHub Release asset

1. Build the installer and verify that `AnimeVault-Setup.exe` exists in the output directory and launches as expected.
2. Open the repository's [Releases page](https://github.com/rudy0senpai/AniListVault/releases) and inspect the release matching the application version.
3. If that release already exists and has no conflicting asset name, upload the built file through the release's **Edit release → Attach binaries** interface or with `gh release upload <tag> <path-to>\AnimeVault-Setup.exe`.
4. Verify the asset is listed on the release page and its download works. Do not create a release or replace an existing asset unless authorized to do so.

Generated `dist/` and `build/` outputs are ignored by Git; do not add the installer to ordinary source commits.

## Installer behavior

The standard installer generated by `build_windows.ps1` and Inno Setup uses the wizard defined in `AnimeVault.iss`. It installs the app files under the `{autopf}\AnimeVault` default, creates a Start-menu shortcut, offers an optional Desktop shortcut, and registers an uninstaller in Windows Apps. The wizard offers to launch the app when setup finishes.

The alternative self-extracting installer generated by `build_installer.py` asks for confirmation, installs under `%LOCALAPPDATA%\Programs\AnimeVault`, creates Start-menu and Desktop shortcuts, registers **AnimeVault** in Windows Apps & features, then offers to launch the app. Its install location and behavior come from that script, not from the Inno Setup file.

## Uninstalling

**Normal way:** Windows → *Apps & features* → **AnimeVault** → Uninstall.

**From this repo:**

```powershell
# Remove the app, keep the library
.\packaging\uninstall.ps1

# Remove the app and delete the library database, posters and settings
.\packaging\uninstall.ps1 -PurgeData
```

## Where user data lives

The library sits **outside** the install folder, so uninstalling never
destroys it:

```
%APPDATA%\AnimeVault\animevault.db   library
%APPDATA%\AnimeVault\posters\       cover images
%APPDATA%\AnimeVault\cache\         provider cache
```

## Notes

- Installer size varies with Python, PySide6, and bundled assets; do not rely on a fixed size estimate.
- Build on Windows — PyInstaller does not cross-compile.
- `build_windows.ps1` requires Inno Setup 6 to produce the standard installer. `build_installer.py` is a separate self-extracting alternative and does not run automatically from the PowerShell script.

## Repairing an older install

Installers built before the uninstall fix shipped an `uninstall.exe` that
was a copy of the installer itself, and left `UninstallString` empty —
so **Uninstall** either did nothing or re-installed the app.

To fix an existing installation without reinstalling:

```powershell
.\packaging\repair_uninstall.ps1
```

It installs the real uninstaller and rewrites the registry entry.
After running it, **Windows Settings → Apps → Installed apps →
AnimeVault → Uninstall** works normally.

## Files

| File | Purpose |
|---|---|
| `build_windows.ps1` | Freezes the app with PyInstaller and optionally compiles the Inno Setup installer |
| `build_installer.py` | Builds the separate self-extracting setup and the uninstaller |
| `uninstaller.py` | Source for `uninstall.exe` |
| `repair_uninstall.ps1` | Fixes the uninstall entry on an older install |
| `uninstall.ps1` | Remove the app; `-PurgeData` also deletes the library |
| `AnimeVault.iss` | Inno Setup installer definition used by `build_windows.ps1` |
